### S2-05 matched-context detail

The acceptance unit is the actual avatar box, not a masked subset:

- Each of the 82 instances is rendered in one page, one fixed grid cell, at integral screen coordinates, `deviceScaleFactor: 1`, with `document.fonts.ready` and two animation frames settled. The populated capture is taken twice. Then **only the other 81 SVG elements are removed**; every cell wrapper, its size, the grid position, the page scroll and every ancestor style remain unchanged. The target element is never replaced or moved. The isolated capture is taken twice, then the siblings are restored.
- The target's `getBoundingClientRect`, every `<text>` bounding box, and computed font/opacity/fill/letter-spacing/line-height/text-rendering properties are recorded before, during and after removal; all 102 target states passed exact equality.
- **Eligible pixels are the whole box**: Chromium 82 × px² = 953,024; Firefox 10 × px² = 88,896; WebKit 10 × px² = 88,896. `eligibleFraction` is **1.0** for every target; there is no text mask, no 2 px interior margin, no antialias padding and no tolerance. Full-image pixel equality includes text glyphs and circular clip edges. Captures use an opaque white page background so the transparent area outside the circular clip is also compared as rendered; the same background is present in both states. With transparent captures, 10/82 Chromium ascii-face targets showed clip-edge-only residuals (47–488 px, max Δ255) while repeats were stable; that compositor-path residual was not masked — the capture context was made identical and the full pixels were re-compared, giving 0 differing pixels.
- **All 102 target comparisons are pixel-identical, 1,130,816/1,130,816 pixels.** Baseline repeats (populated A/B and isolated A/B) are also identical for all 102, so the result is not a stable-but-wrong comparison. Each engine covers 8 styles; Firefox/WebKit cover one target per style plus both exact repeats at the same coordinates, while Chromium covers all 82.
- **Definitions remain independent:** 100 distinct IDs, 102 definitions, 2 repeated IDs, **0 cross-document conflicts**, **0 within-document conflicts**.
- **Text is no longer excluded:** the ASCII text-glyph control changes 118 pixels (0.819% of the 120 px target, max channel delta 201) and the ASCII text-opacity control changes 104 pixels (0.722%, max delta 100); both are rejected by the production comparator. A clean identical-document positive control accepts all 14,400 eligible pixels, so the comparator is sensitive rather than blanket-rejecting.
