## WebKit CSP steering (Stage 6 warning attribution)

The Stage 6 S6-07 WebKit warning is **reproducible**, but the original "browser-injected" attribution was incomplete. The exact event at the Stage 6 fallback URL (`?seed=fallback-webkit&style=ascii-letter&name=Ada`) is:

```json
{"violatedDirective":"style-src-attr","effectiveDirective":"style-src-attr","blockedURI":"inline","sourceFile":"","lineNumber":26,"columnNumber":1,"sample":"","disposition":"enforce"}
```

Console text: `Refused to apply a stylesheet because its hash, its nonce, or 'unsafe-inline' does not appear in the style-src directive of the Content Security Policy.` It occurs once at **page load**; the manual-copy fallback adds **no new violation** (manual snapshot has the same single event).

Control matrix (WebKit 27.2, same strict CSP):

| --- | --- |
| blank page, no app | **no** |
| app page without `assets/app.js` | **yes** |
| full HTML without controls | **no** |

| insert generated SVG (all styles) | **no** |

| HTML `style` attribute control | **yes** (detector sanity) |

**Exact trigger: the native `<select id="size">` control**, not app inline SVG presentation attributes and not web-inspector/tool injection. The select still works under CSP: changing 80→128 updates `#svg-source` and preview width to 128, then back to 80. The generated SVG computed first fill is `rgb(169, 232, 235)` (presentation fill applied), all 8 WebKit outputs match the installed package for this URL, and the data URL image loads. This is a WebKit 27.2 CSP `style-src-attr` reporting limit for the native select, not required code/script/eval being blocked. No product fix or extra stage was made.
