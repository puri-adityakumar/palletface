## Finding S1-06 — ascii-letter name changes seeded dot field (S1, blocker candidate)

**Expected (API.md):** `name` “does not affect seeded background/color choices”; only the glyph should change.
**Actual:** for `asciiLetter(seed, 80, name)`, dot positions outside both compared glyphs change when only `name` changes. Root size, viewBox, clip ID, background rectangle, and color choices stay equal; the seeded dot layout does not.

| Comparison (same seed `seed-background-check`, px 80) | Differing dots outside both glyphs |
| --- | ---: |
| `Alice` vs `Bob` | 10 |
| `Zoe` vs `9lives` | 16 |
| `Élodie` vs `用户` | 17 |

Examples from `Alice` vs `Bob`: `(6.5,1.5)` and `(3.5,3.5)` have a dot only for Alice; `(7.5,1.5)` and `(4.5,3.5)` have a dot only for Bob. These cells are outside the A and B glyph boxes, so this is not glyph replacement.

**Cause (not fixed, product forbidden in this stage):** `src/styles/ascii-letter.ts:49` consumes `r()` only for non-glyph cells. A different initial changes which cells consume the PRNG stream, shifting all later dot decisions.

**Impact:** changing a display name at a fixed seed alters the ascii-letter background, contradicting the documented name/background invariance. `pixelLetter` and `pixelifyLetter` passed the same structural comparison (background cells and clip unchanged).
