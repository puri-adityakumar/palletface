Every state had **0 violations of any impact** (**0 serious, 0 critical, 0 moderate, 0 minor**); each run reported 43 passing nodes.
- **Incomplete, not violation:** `aria-prohibited-attr` (serious) on `#gallery` because the generic `<div>` has `aria-label="Avatar styles"`. Manual assessment: the visible `<h3>All eight styles</h3>` and separately named style buttons preserve the task; this is recorded as a minor semantic observation (S8-O1), not a control-name failure. It is not waived.
- **Incomplete, not violation:** `color-contrast` on the decorative `aria-hidden` `.pixel-mark`, generated SVG `<text>` inside the `aria-hidden` preview, and open textareas. Manual computation found the textarea text itself high-contrast; the SVG is decorative and the preview has a role/label. The genuine text contrast failure is the S8-07 placeholder finding.
- Negative control: the same axe scanner detected the bounded missing-label input (`label`) and low-contrast text (`color-contrast`); the clean site had no serious/critical violations.
- **Q-002 recheck:** blocking `/assets/app.js` with scripting enabled left static content readable (1,995 characters) and the controls present, but `#preview` and `#gallery` were empty and `#status` was empty; no explanatory failure message. ## S8-05 — zoom and reflow

- Chromium CDP `Emulation.setDeviceMetricsOverride` produced real **layout-viewport equivalences**: 640 CSS px for 1280 at 200%, 320 CSS px for 1280 at 400%. At both widths `innerWidth === scrollWidth`, no horizontal overflow, no hidden/clipped text, and the page remained functional. This is explicitly **layout equivalence, not CSS `zoom` and not a claim of native page-zoom visual scaling**.
- A separate pinch-zoom diagnostic (`Emulation.setPageScaleFactor`) reported visual scale 4 while the layout viewport stayed 1280; it was **not** used for the reflow claim.
- At 320, all 24 controls remained keyboard-reachable and horizontally inside the viewport. Firefox and WebKit at 320 also showed no overflow or clipping.
- Synthetic 200% text enlargement at 1280 doubled text-element font sizes; no page overflow or hidden clipping was found and 17 controls remained rendered. This is a declared stress method, not a native text-only-zoom claim.
- The 320/640 full-page samples were captured from separate real Playwright viewports at the same CSS widths because Chromium 156's CDP-surface full-page capture visibly clipped the surface while the DOM measurements reported no overflow. These are **layout-equivalent visual samples**, not CSS zoom. Inspected outcomes: 320 one-column controls/two-column gallery and 640 two-column controls/two-column gallery both fit and wrap without clipping.
